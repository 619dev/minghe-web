01 / BUILT TO CONNECT

軽量なコアで、
すべての通話を大切に。

複雑なプロトコルを、シンプルな体験へ。
シグナリングからメディアまで、セルフホスト音声通信に必要な機能を。

⌑01

通信経路を暗号化

TLS 1.2 / 1.3 で SIP シグナリングを、SRTP で音声メディアを保護。内線ごとのパスワードと Digest 認証に対応します。

TLS + SRTP
⌘02

Pure Rust、シンプルで力強く

メモリ安全な Rust と Tokio 非同期ランタイムで構築した、GC を持たない最小限の SIP サーバーです。

RUST NATIVE
↗03

自分のネットワークを、自分で管理

自分の VPS に導入して内線を管理。音声通話、SIP テキストメッセージ、オフライン時の一時保管と再配信に対応します。

SELF-HOSTED

暗号化について：中継サーバーはメディアを復号して再暗号化するため、信頼境界に含まれます。エンドツーエンド暗号化ではありません。オフラインメッセージはメモリ内に保管され、再起動すると失われます。

    ソースを取得

    リポジトリをクローンし、Docker と Compose を用意します。

  2. 2

  3. 3

GOOD TO KNOW

接続する前に、
知っておきたいこと。

MingHe を Vercel に導入できますか？+

この紹介サイトは Vercel に直接導入できます。MingHe SIP サーバーには固定 TCP シグナリングポートと固定 UDP メディアポート範囲が必要です。対応する VPS または自前のサーバーをご利用ください。

どのクライアントを使えますか？+

プロジェクトでは Bria Mobile と Linkvil W610W / W620W を推奨しています。その他の端末には SIP over TLS、SDES-SRTP、適切な証明書の信頼設定が必要です。Tantuns H5 では別途確認してください。

自己署名証明書はどう設定しますか？+

サーバーの certs/server.crt を信頼済み証明書としてクライアントに取り込み、証明書検証を有効にします。更新後はクライアントの信頼設定も更新してください。公開環境では信頼できる CA の証明書を推奨します。

MingHe はオープンソースですか？+

はい。Apache-2.0 ライセンスで公開されています。GitHub でソースの閲覧、問題の報告、開発への貢献ができます。
